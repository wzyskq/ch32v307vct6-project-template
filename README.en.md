# CH32V307VCT6 Project Template

## Overview

This repository is based on [MRS2 (MounRiver Studio Ⅱ)](https://www.mounriver.com) **V220** and has been modified for compatibility with the VSCode [Embedded IDE](https://em-ide.com) plugin.

## Usage

### Prerequisites
1. Configure the toolchain and corresponding OpenOCD path for VSCode EIDE. Refer to the tutorial: [VSCODE-EIDE编译调试CH32V307 - Zhihu](https://zhuanlan.zhihu.com/p/1922436930869626702)
2. Download the **repository zip** or get this project via **Git**:
```git
git clone https://github.com/wzyskq/ch32v307vct6-project-template.git
```

### MRS2
Open the `.mrs/CH32V307VCT6.wvproj` file with MRS2, then build and flash as usual.

### Embedded IDE
There are two configuration schemes. Scheme 1 is the default. If you encounter a 20s wait for verification after flashing, try Scheme 2.

**Scheme 1**

Open the `.vscode/CH32V307VCT6.code-workspace` workspace file in VSCode, then build and flash.

**Scheme 2**

Open the `.vscode/CH32V307VCT6.code-workspace` workspace file in VSCode. Modify the flashing script `download.cmd` (for Mac/Linux, you need to convert it manually) in the same directory to set the OpenOCD path to your local path. Open `.vscode/.eide/eide.yml` and change the last line from `uploader: OpenOCD` to `uploader: Custom`. Follow the prompts in VSCode to update EIDE, then build and flash (make sure the toolchain and OpenOCD path are configured in EIDE first).

**Scheme Explanation**

At one point, I encountered a situation where Scheme 1 could flash but failed verification at the end, requiring a 20s wait (even though the program was already flashed and running before the wait). So I rewrote the `download.cmd` script to remove the verification step. If Scheme 1 works for you, it is recommended to use Scheme 1.

## Project Structure

**Main Project Tree**:
```cmd
.
├─.mrs
│  ├─.mrs
│  └─obj      (MRS2 build output)
├─.vscode
│  ├─.eide
│  ├─.vscode
│  ├─obj      (EIDE build output)
│  └─tools    (OpenOCD flashing interface files)
├─device      (driver files, other code)
├─sdk         (software development kit)
│  ├─Core
│  ├─Debug
│  ├─Ld
│  ├─Peripheral
│  │  ├─inc
│  │  └─src
│  └─Startup
└─user        (main function/interrupt files)
```

**Additional Note**  
- The `.mrs` and `.vscode` directories in the root folder were created by myself; 
- the subdirectories `.mrs` and `.vscode` within them are the configuration files generated by MRS2 and VSCode, respectively.
